# Парсинг сайтов

Три продукта, которые вместе закрывают полный цикл сбора данных с сайтов поставщиков:
от разведки «можно ли парсить и как» до регулярного обхода каталогов и точечного
скрейпа карточек по запросу.

## Продукты

| Продукт | Что делает | Кейс |
|---|---|---|
| **catalog-scraper** | фреймворк регулярного обхода каталогов → БД | [catalog-scraper](catalog-scraper/README.md) |
| **site-reconnaissance** | разведка сайта: как парсить, есть ли антибот | [site-reconnaissance](site-reconnaissance/README.md) |
| **product-card-scraper** | точечный live-скрейп карточки по артикулу | [product-card-scraper](product-card-scraper/README.md) |

---

## 1. Связки для чеккинга сайтов (разведка)

Прежде чем писать парсер, сайт прогоняется через **связку из трёх инструментов**
(`site-reconnaissance`), каждый даёт свой срез:

```
                 ┌─────────────────────────────────────────────┐
   URL сайта ──► │ 1. scrapalyser   быстрый скан (без браузера)  │
                 │    → техстек, CMS, фреймворки, заголовки      │
                 │                                              │
                 │ 2. api-recon     браузерный обход (Playwright)│
                 │    → перехват XHR/fetch, поиск скрытых JSON   │
                 │      API, генерация отчёта по эндпоинтам      │
                 │                                              │
                 │ 3. caniscrape    диагностика антибот-защиты   │
                 │    → Cloudflare/капчи, блокировки по гео/UA,  │
                 │      оценка сложности 0–10                    │
                 └─────────────────────────────────────────────┘
                                   │
                                   ▼
                    JSON-отчёт → решение «как парсить»
```

Зачем три, а не один: **scrapalyser** работает быстро (curl-движок) и показывает базовую
картину; **api-recon** находит то, что не видно в HTML (данные грузятся через API — значит,
парсить надо API, а не страницы); **caniscrape** оценивает, не заблокируют ли нас и какая
нужна антибот-обвязка.

## 2. Аналитика способа парсинга

Отчёт разведки формализует решение о том, **как** парсить сайт:

| Признак (из отчёта) | Способ парсинга |
|---|---|
| статический HTML, sitemap.xml есть | **HTTP-обход** по sitemap (curl/httpx) |
| данные грузятся через XHR/JSON | **JSON API** — парсить эндпоинты напрямую (быстрее и надёжнее) |
| JS-рендер, контент появляется динамически | **Headless** (Playwright) |
| антибот, капча, блок по гео | **антибот-обвязка**: прокси, impersonation, лимит темпа |
| только прайс-файл (xls/pdf), сайта нет | **файловый парсинг** (см. тему «документы») |

Это решение передаётся в конфиг парсера (`parser_type`, `js_required`, `antibot`,
`api_endpoints`, `sitemap_url` в БД), и дальше `catalog-scraper` работает уже по выбранному
подходу.

## 3. Разные подходы в самом парсинге

`catalog-scraper` — фреймворк с **реестром парсеров**: каждый поставщик = отдельный
парсер-плагин, ядро общее. Подходы:

- **Трёхстадийный пайплайн** — `каталог → список URL → детали карточек`, каждая стадия
  идемпотентна и возобновляема (`/parse`, `/parse/resume`, `/parse/stop`, `/parse/progress`).
- **Движки**: curl/httpx (статика) и Playwright (JS-сайты) — выбирается на парсер.
- **Анти-бан**: token-bucket ограничение темпа (`rate_rps`), retry с экспоненциальной
  задержкой, ротация User-Agent, impersonation через curl_cffi.
- **Персистентность**: сырые страницы кэшируются (`raw_pages`), товары upsert-ятся по ключу
  `(supplier_id, external_id)`, цены/остатки пишутся в историю — повторный обход не
  перескачивает уже обработанное.
- **Файловые источники**: если каталога-сайта нет — разбор прайс-листов (xls/pdf) в тот же
  каталог.

## 4. Как использовать (сквозная инструкция)

```bash
# Шаг 1. Разведка нового сайта
curl -X POST http://<host>:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/catalog", "deep": true, "diagnostics": true}'
# → JSON-отчёт: техстек, API-эндпоинты, антибот, оценка сложности

# Шаг 2. Написать парсер по отчёту (реестр в catalog-scraper)
#    реализовать fetch_catalog / fetch_product_urls / fetch_product_details
#    и зарегистрировать parser_id

# Шаг 3. Запустить обход
curl -X POST http://<host>:8003/parse \
  -H "Authorization: <ваш-токен>" \
  -d '{"parser_id": "my_parser"}'
curl http://<host>:8003/parse/progress?parser_id=my_parser

# Шаг 4. Точечная карточка по артикулу (без БД, live)
curl "http://<host>:8002/product?article=1R-D.001-12"
```
